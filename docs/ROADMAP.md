## Tier 5 — version upgrades (legacy pain point)

Help users move a project from one JHipster generator version to another — historically one of JHipster's biggest friction points. The official `jhipster upgrade` is **git-based** (branch → regenerate → merge), which collides with this server's *no-git / `--skip-git`* principle, so the plan favors **git-free, isolation-based** approaches that play to the server's existing machinery, and defers the git-wrapping route.

| # | Item | Status | Notes |
|---|------|--------|-------|
| 13 | **Upgrade advisor** — read-only pre-flight: detect the current generator version from `.yo-rc.json`, compare to a target version, and surface known breaking changes / migration steps / effort. | ⬜ | Lowest risk, highest value-to-effort. Pure read; reuses the `jhipster://project/yo-rc` resource. The agent supplies the breaking-change knowledge; the tool/resource supplies the facts (current vs. target version, applicationType, blueprints). Could ship as a tool, a resource, or a prompt — decide at design time. |
| 14 | **JDL re-generation + diff** — export the project's JDL, regenerate it in isolation **using the target generator version**, and return a structured diff of what would change. | ⬜ | The flagship, git-free upgrade aid. Reuses `exportJdlIsolated` + `runJdlIsolated`. Open questions: how to select/install the target generator version for the isolated run (vs. always using the global `jhipster`); how to represent the diff (per-file actions like the existing parser, or a real text diff). Limitation: only covers JDL-expressible structure — custom code in generated files is still the user's git merge, same as `jhipster upgrade`. |
| 15 | **Wrap `jhipster upgrade`** — a dedicated tool orchestrating the official git-based upgrade command. | ❄️ | **Deferred** — requires relaxing the *no-git / `--skip-git`* principle and handling target-version install. Revisit only if users specifically want the official merge flow rather than the git-free diff in #14. `upgrade` is already reachable today via the `run_jhipster` allowlist for the adventurous. |

## Design principles to preserve

- Non-interactive always (`--force --skip-git`, `CI=true`).
- No shell (`spawn` with `shell: false`); validate user-influenced args.
- Build JDL via the validated builders in [src/jdl/builders.ts](../src/jdl/builders.ts), never hand-concatenate.
- Every tool takes an absolute `workingDirectory`.
- Keep the test approach: `node:test` + `tsx`, in-memory MCP pair, fake `jhipster` on PATH.
